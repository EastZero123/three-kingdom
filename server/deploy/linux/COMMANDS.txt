삼국지 원정 로그라이트 — 온라인 랭킹 서버 명령어 모음
=====================================================
이 파일은 install.sh가 /opt/samgukji/COMMANDS.txt 로 복사합니다. 보기: less /opt/samgukji/COMMANDS.txt
명령 앞에 sudo가 붙은 것은 관리자 권한이 필요합니다.


1. 설치 위치
------------
  /opt/samgukji/ranking-server.jar      서버 프로그램
  /opt/samgukji/game/                   검증용 게임 파일 (Godot가 기록을 다시 실행할 때 씀)
  /opt/samgukji/godot/godot             Linux용 Godot
  /etc/samgukji-ranking.env             환경 변수 (DB 비밀번호 등, root만 읽기 가능)
  /etc/systemd/system/samgukji-ranking.service   서비스 등록 파일
  서비스 사용자: samgukji      서비스 이름: samgukji-ranking      포트: 9090


2. 서비스 켜기·끄기
-------------------
  상태 보기          sudo systemctl status samgukji-ranking
  시작               sudo systemctl start samgukji-ranking
  중지               sudo systemctl stop samgukji-ranking
  다시 시작          sudo systemctl restart samgukji-ranking
  부팅 때 자동 시작  sudo systemctl enable samgukji-ranking     (install.sh가 이미 켜 둠)
  자동 시작 끄기     sudo systemctl disable samgukji-ranking
  떠 있는지 확인     ps -ef | grep ranking-server.jar


3. 로그 보기 (서버 로그는 systemd 일지에 쌓인다)
-----------------------------------------------
  최근 100줄             sudo journalctl -u samgukji-ranking -n 100 --no-pager
  실시간으로 따라 보기   sudo journalctl -u samgukji-ranking -f          (끝내기: Ctrl+C)
  오늘 로그만            sudo journalctl -u samgukji-ranking --since today --no-pager
  검증 관련만            sudo journalctl -u samgukji-ranking --no-pager | grep -i 검증
  오류만                 sudo journalctl -u samgukji-ranking -p err --no-pager


4. 환경 변수 (DB 접속 정보, 포트)
---------------------------------
  열어서 고치기          sudo nano /etc/samgukji-ranking.env
  고친 뒤에는 반드시     sudo systemctl restart samgukji-ranking
  항목: DB_URL, DB_USERNAME, DB_PASSWORD, PORT, GODOT_PATH, GAME_PROJECT_PATH


5. API 확인 (서버 안에서)
-------------------------
  온라인 순위            curl http://localhost:9090/leaderboard
  순위 상위 5개          curl "http://localhost:9090/leaderboard?limit=5"
  기록 하나 상태         curl http://localhost:9090/runs/1          (1 자리에 기록 번호)
  포트를 듣고 있는지     sudo ss -ltnp | grep 9090                 (*:9090 이면 외부 접속 가능)

  밖(Windows PowerShell)에서 연결 확인:
    (Test-NetConnection 115.68.179.150 -Port 9090).TcpTestSucceeded      → True 면 정상


6. 새 버전으로 업데이트
-----------------------
  [Windows] 묶음 만들기 (게임 폴더에서)
    powershell -ExecutionPolicy Bypass -File server\deploy\package_linux.ps1
    → build\linux\samgukji-ranking-linux.tar.gz 가 생긴다

  [Windows] 서버로 올리기 (예: scp, 사용자 이름은 실제 계정으로)
    scp build\linux\samgukji-ranking-linux.tar.gz 사용자@115.68.179.150:~/

  [서버] 풀고 설치 (환경 변수 파일은 그대로 두고 jar·게임 파일만 바꾼 뒤 서비스를 다시 켠다)
    rm -rf samgukji-deploy && mkdir samgukji-deploy
    tar -xzf samgukji-ranking-linux.tar.gz -C samgukji-deploy
    cd samgukji-deploy && sudo bash install.sh
    → 6/6 단계에 "통과"가 나와야 한다 (Windows와 같은 결과가 나온다는 뜻)

  주의: 게임 버전(project.godot의 config/version)이 바뀌면, 서버를 먼저 업데이트한 뒤
        새 exe를 배포한다. 서버가 옛 버전이면 새 버전 기록은 모두 game_version 으로 거부된다.


7. 검증만 따로 해 보기 (Windows에서 만든 표본 기록을 이 서버의 Godot로 재실행)
-----------------------------------------------------------------------------
  sudo -u samgukji HOME=/opt/samgukji /opt/samgukji/godot/godot --headless --path /opt/samgukji/game \
      -s verify/verify_run.gd -- /opt/samgukji/sample_verify_input.json | grep VERIFY_RESULT
  → "ok":true 면 통과. result_mismatch / replay_diverged 면 운영체제 간 결과가 다르다는 뜻.
  Godot 버전 확인         /opt/samgukji/godot/godot --headless --version


8. DB 들여다보기 (읽기만)
-------------------------
  접속                   mysql -u cdy -p samgukji_ranking
  상태별 개수            SELECT status, COUNT(*) FROM run_submissions GROUP BY status;
  최근 기록 10개         SELECT id, player_name, game_version, claimed_years, verified_years, status, reject_reason, created_at
                         FROM run_submissions ORDER BY id DESC LIMIT 10;
  거부 이유별 개수       SELECT reject_reason, COUNT(*) FROM run_submissions WHERE status = 'REJECTED' GROUP BY reject_reason;
  검증 대기 중           SELECT id, player_name, created_at FROM run_submissions WHERE status = 'PENDING';
  나가기                 exit

  상태 뜻: PENDING = 검증 대기 (서버 쪽 문제로 미뤄졌으면 서버를 다시 켤 때 다시 검증)
           VERIFIED = 통과, 순위에 보임      REJECTED = 거부 (reject_reason에 이유)
  기록 삭제(DELETE)는 되돌릴 수 없다. 지우기 전에 위의 SELECT로 대상을 꼭 확인한다.


9. 방화벽 (확인만 — 바꾸는 것은 직접 판단)
-----------------------------------------
  상태 보기              sudo ufw status verbose
  9090 열기 (필요할 때)  sudo ufw allow 9090/tcp
  호스팅 업체 방화벽(보안 그룹)도 9090/tcp 인바운드가 열려 있어야 한다.
  DB 포트 3306은 지금처럼 관리자 PC에서만 접속하게 둔다.


10. 문제가 생겼을 때 볼 순서
---------------------------
  1) sudo systemctl status samgukji-ranking          서비스가 active (running) 인가
  2) sudo journalctl -u samgukji-ranking -n 100 --no-pager   마지막 오류 메시지
  3) curl http://localhost:9090/leaderboard           서버 안에서 응답하는가
  4) sudo ss -ltnp | grep 9090                        포트를 듣고 있는가
  5) 밖에서 연결이 안 되면 → 9번 방화벽
  6) 기록이 계속 REJECTED 면 → 8번에서 reject_reason 확인, 7번으로 검증 직접 실행
